NEXLOOT COMPANION APP + WEBAPP – SETUP GUIDE (Companion app 1.8.2)
==================================================================

Note: the companion app and its Discord posts are in German. This guide quotes the German
labels you will see, with the English meaning in brackets. The website is in English and German.


What is what?
-------------
* NexLoot add-on (0.26.0 or newer, 0.29.0 for the guild overview, 0.30.0 for raid setups in game):
  every player needs it. It works fine without anything below.
* Database (Supabase, free): stores your guild's state (coins, history, sessions, permissions,
  guild roster, raid setups) and takes 10 % off all coins every Wednesday at 05:30 (Central
  European Time).
* Website (Netlify, free): shows everyone the current state – leaderboard, history with filters,
  sessions with answers and rolls, statistics, guild, raids and rules. English and German, works on
  phones. Coins, loot and history are not changed there, only in the game. Players who log in with
  Discord see their character on the start page; officers plan raid setups there (step 8). Connected
  to Raid-Helper, the website shows the sign-ups and lets Raid-Helper post the setup (step 10).
* Companion app (Windows): a small program in the system tray, only for officers / the loot master.
  It uploads the state from WoW to the database and brings newer data back into the game, including
  the published raid setups. Optional: posts every raid, the weekly decay, level milestones and the
  raid setups to Discord, and emails a backup every evening.

Every guild sets up its own system: its own database, its own website, its own password.
There is no shared server. Nobody but you can reach your data.

Done once by the guild leader: steps 1 and 2 (about 15 minutes).
Every officer / loot master: step 3 (about 3 minutes).
Optional: Discord (step 4), email backup (step 6), Discord login and raid setups (steps 8 and 9),
Raid-Helper (step 10).


1. SET UP THE DATABASE (Supabase)
---------------------------------
1. Sign up for free at https://supabase.com and create a new project
   (name e.g. "NexLoot", a region near you; you won't need the database password later).
2. Open the file nexloot.sql in the folder "1 Supabase" with a text editor. At the very bottom:
       values ('MyGuild', extensions.crypt('HIER-EIN-LANGES-PASSWORT', ...
   * 'MyGuild' is your guild ID. Replace it with a name of your own, e.g. your guild name.
     The same ID goes into config.js and the companion app later.
   * Replace HIER-EIN-LANGES-PASSWORT ("put a long password here") with your own write password
     (long, no single quote '). Only officers get it.
3. In Supabase, open "SQL Editor" on the left, paste the whole file and press "Run".
   You should see "Success. No rows returned" (lines saying "NOTICE" are normal).
   If you get an error about "pg_cron": on the left go to "Integrations" -> "Cron" -> "Enable"
   (or "Database" -> "Extensions" -> turn on "pg_cron") and run the file again.
4. Run nexloot_gilde.sql (guild overview) and nexloot_konten.sql (Discord login, raid setups) the
   same way, one after the other. Nothing to change in these two.
5. Write down two values:
   * Project URL: click "Connect" at the top, or Project Settings -> Data API
     (looks like https://abcdefgh.supabase.co)
   * Public key: Project Settings -> API Keys, the "Publishable key"
     (starts with sb_publishable_). Or the "anon" key under "Legacy API Keys".
   NEVER use or share the "secret" / "service_role" key.

Changing the password: run the last lines of nexloot.sql (from "insert into public.nexloot_secret")
again in the SQL Editor with the new password. Then enter the new password in every companion app.

All .sql files can be run again safely. When the files are updated, just run the new ones again –
coins, history, accounts and setups are kept.


2. PUT THE WEBSITE ONLINE (Netlify)
----------------------------------
1. Open config.js in the folder "2 Website" with a text editor and fill in:
       supabaseUrl: "https://abcdefgh.supabase.co",
       anonKey: "sb_publishable_...",
       guild: "MyGuild"          (your guild ID from step 1)
   Save.
2. Sign up for free at https://app.netlify.com (sign in first, otherwise the site is only
   online for a short time).
3. Drag the whole folder "2 Website" onto https://app.netlify.com/drop.
   Done: the site runs at an address like https://randomname.netlify.app.
4. Under "Site configuration" -> "Change site name" pick your own name,
   e.g. https://my-guild-loot.netlify.app.

The site reloads the data every minute. Until an officer runs the companion app, it says
"No data yet". If you open index.html without a filled-in config.js, it shows sample data.
The "Log in with Discord" button only appears after step 8.

New version of the website: drag the folder "2 Website" with the new index.html and your filled-in
config.js onto your site at Netlify again ("Deploys" -> drop the folder).


3. COMPANION APP (every officer / loot master)
----------------------------------------------
Before you start: NexLoot 0.26.0 or newer installed, and logged in once with your character.
Windows 10 or 11. Nothing to install: the app uses the Windows PowerShell built into Windows.

1. Before unzipping: right-click the ZIP file -> Properties -> tick "Unblock" at the bottom -> OK.
   (Otherwise Windows asks every time it starts.)
2. Copy the folder "3 Companion" to a permanent place, e.g. Documents\NexLoot Companion.
3. Double-click "NexLoot Companion.bat". The first start opens the setup window:
   * "Verbindungscode" (connection code): you get it from your guild leader (see below). Paste it
     and the fields for Supabase address, key, guild and password fill in by themselves.
     The guild leader enters the values from steps 1 and 2 by hand:
     "Supabase-Adresse" (Project URL), "Öffentlicher Schlüssel" (public key),
     "Gilde (Kennung)" (guild ID), "Schreib-Passwort" (write password).
   * "Dein Charaktername" (your character name, shown on the website as "changed by").
   * WoW: found automatically (e.g. "_classic_ - Konto 12345678#1"). If not, click
     "WoW-Ordner selbst wählen …" (choose WoW folder) and pick the folder that contains WTF and
     Interface.
   * "Webapp-Adresse" (website address, optional): the menu can then open the website.
   * "Verbindung testen" (test connection), then "Speichern" (save).
4. A golden N appears in the system tray (maybe behind the small arrow ^). Right-click it for the
   menu. "Mit Windows starten" (start with Windows) is on, so the data stays current even if you
   were offline for a week.
5. Type /reload in the game once. The app uploads the state and the website shows it.

Change settings later: right-click the N -> "Einstellungen …" (settings), or double-click
"NexLoot Companion - Setup.bat".

Connection code for more officers: right-click the N -> "Verbindungscode für andere Offiziere
kopieren" (copy connection code for other officers) and send it PRIVATELY only (it contains the
write password).

Updating to a newer version: right-click the N -> "Beenden" (quit), copy the new files over the
old ones (your settings are kept) and double-click "NexLoot Companion.bat".


4. DISCORD (optional, no bot needed)
------------------------------------
After every raid the companion app posts a summary to a Discord channel: who got which item (with
choice and coins, the item name links to Wowhead), the raid points (bench included) and below that
the coins of all players, sorted and numbered (the change in this raid in brackets). If it gets too
long for Discord, the coins go into a second message. All you need is a webhook. Raid setups and
level milestones can go there too (steps 7 and 9).

1. In Discord: right-click the channel -> "Edit Channel" -> "Integrations" -> "Webhooks"
   -> "New Webhook". Name it e.g. "NexLoot", then "Copy Webhook URL".
   (You need the "Manage Webhooks" permission on the server.)
   Nicer: upload "NexLoot-Logo.png" from the folder "3 Companion" as the webhook's avatar.
2. Right-click the N -> "Einstellungen …" (settings) -> paste into "Discord-Webhook" ->
   "Discord testen" (a test message appears in the channel) -> "Speichern" (save).
3. "Dein Charaktername" must be spelled exactly as in the game. Your app then posts the raids you
   led as soon as you log out or /reload.
   If the raid was led by someone without the app and webhook, your app posts it after
   30-40 minutes. Every raid is posted only once, even if several officers entered the webhook.
   Raids from before you entered the webhook are not posted.
4. Send again: right-click the N -> "Letzten Raid nach Discord senden" (send last raid to Discord).
5. If a raid that was already posted is reopened and changed, the app does not post a second full
   summary, only a correction: what was taken back (struck through), what was added and the new
   coins of the players affected. Without a change, nothing is posted.
6. Weekly decay: on Wednesdays after the decay in the database (05:30), the app posts
   "📉 Wöchentlicher Verfall −10 %" (weekly decay) with all players and their new Nex-Coins. It is
   posted exactly ONCE, even if several officers run the app with a webhook. If no PC was on that
   Wednesday, the first app that starts within 2 days posts it.

The webhook address is like a password: anyone who has it can write to the channel. The app stores
it encrypted; it is never in the log or in the connection code. If it leaks anyway: delete the
webhook in Discord and create a new one.


5. COIN DECAY
-------------
The database does the weekly decay itself (set up by nexloot.sql in step 1): every Wednesday at
05:30 Central European Time, 10 % off all coins. The add-on no longer takes anything off by itself.
The companion apps bring the new state into the game like any other change.
* Check that the schedule runs (SQL Editor):  select jobname, schedule, active from cron.job;
* If the Supabase project was paused (see "How the sync works"), the database makes up a missed
  decay as soon as it runs again.


6. EMAIL BACKUP (optional)
--------------------------
Every evening the app emails a backup of the database as "NexLoot-Sicherung-<date>.sql": first
CREATE TABLE, then the complete state (coins, history, sessions with answers and rolls,
permissions, item names ...). That is enough to restore everything. One officer setting this up
is enough (ideally the guild leader).

Setup (with a Gmail account as sender, about 3 minutes):
1. Create an app password for the Gmail account that will send the mails:
   https://myaccount.google.com/apppasswords (name e.g. "NexLoot") -> you get a 16-letter
   password. If the page doesn't work, first turn on 2-Step Verification under "Security".
   Your normal Gmail password does not work here.
2. Right-click the N -> "Sicherung per Mail …" (backup by email):
   - tick "Jeden Abend eine Sicherung per Mail schicken" (send a backup every evening)
   - "Empfänger" (recipient): your address
   - "Absender" (sender): the Gmail address from step 1, "App-Passwort": the password from step 1
     (spaces don't matter)
   - "Mailserver" smtp.gmail.com, port 587 (preset), "Uhrzeit" (time) e.g. 22
3. "Test-Sicherung jetzt senden" (send test backup now) -> the mail with the file arrives (check
   spam too). Then "Speichern" (save).

From then on a mail goes out every evening from the time you set. If the PC was off, the app sends
the backup on its next start. Send one right away: right-click -> "Sicherung jetzt per Mail
senden". Other mail providers work too (enter their server and port, encrypted with STARTTLS,
usually port 587).

Restoring (emergencies only, e.g. if the Supabase project is gone):
1. New project: run nexloot.sql, nexloot_gilde.sql and nexloot_konten.sql first (as in step 1).
2. Supabase -> "SQL Editor" -> paste the whole .sql file from the mail -> "Run".
   It replaces the guild's state with the backup.
3. New project = new address and key: update config.js of the website and the settings of the
   apps. After that the companion apps sync as usual. Set up the Discord login (step 8) again in the
   new project.


7. GUILD OVERVIEW, MILESTONES, WELCOME MESSAGE (add-on 0.29, companion app 1.7.0 or newer)
-----------------------------------------------------------------------------------------
The website has a guild tab ("Guild"): every member with level, class, rank and when they were last
online, plus role (tank / healer / damage), talent points and professions from everyone with
NexLoot 0.29. At the top: raid planning at level 60 (how many tanks, healers and damage dealers,
which classes). Below that: the level milestones (25, 40, 60, including the guild's first level 60).

Where does the data come from? The add-on of every officer keeps the guild roster (the game knows it).
The companion app uploads it whenever WoW saves (logout or /reload). Members don't have to do anything.
Role, talents and professions come from every player's add-on. Each player sets their role in game:
/nex -> Options -> "My raid role" (or /nex role healer). In game, /nex guild shows the state.

Setup: nexloot_gilde.sql already ran in step 1. Officers need companion app 1.7.0 or newer and
add-on 0.29.0, everyone else add-on 0.29.0.

Milestones on Discord: when someone passes level 25, 40 or 60, the app posts it to your channel (in
German, e.g. "🏆 … ist Level 60 – der erste 60er der Gilde!" = the guild's first level 60). It is on as
soon as a webhook is entered: settings -> "Gilden-Meilensteine posten" (post guild milestones). For a
separate channel, enter a second webhook under "Webhook Meilensteine"; empty means the same channel as
the raids. Each milestone is posted exactly once, even with several officers. It shows up a few minutes
after an officer logs out or types /reload.

Welcome message (in game, officers only): /nex -> Options -> "Welcome message" -> "Text ...": enter your
Discord and website links and adjust the text ({name} = first name, {guild}, {discord}, {webapp}).
"Send to me" shows how it looks, "Save" keeps it. Then switch it on. New members get it once as a
whisper, from one officer only, even if several have it on.

Fresh start (e.g. on a new server): run "1 Supabase/nexloot_gilde_reset.sql" in the SQL Editor. It
clears the roster and the milestones, so the next level 60 counts as the guild's first again.


8. LOG IN WITH DISCORD, "MY CHARACTER" AND RAID SETUPS (website)
----------------------------------------------------------------
* "Log in with Discord" at the top right. Then everyone picks their character from the guild roster
  ("That's me") and sees it on the start page: Nex-Coins with rank, items, attendance and the next raid
  with their own group. Alts: name at the top -> "My characters …". The star makes a character the
  favorite for the start page. You stay logged in in that browser until you choose "Log out".
* "Raids" tab: the published raid setups for everyone – groups, bench, "Not attending", with counts of
  tanks, healers, damage and classes. Your own character is highlighted. Below: "Past raids" with all
  old setups and who actually showed up.
* Officers plan the setups and, in the "Admin" tab, assign Discord accounts to characters, also for
  players who never log in.
You become an officer on the website by logging in with Discord and entering the guild's write
password once (the same as in the companion app): name at the top -> "Unlock as officer …". The
password is not stored. Officers can make others officers or members again in the admin tab (not
themselves).

One-time setup (guild leader, about 10 minutes):
1. nexloot_konten.sql already ran in step 1.
2. In Supabase, on the left: "Authentication" -> "Sign In / Providers" -> expand "Discord". It shows the
   "Callback URL" (https://<your-project>.supabase.co/auth/v1/callback) -> "Copy". Keep the page open.
3. Create a Discord application: https://discord.com/developers/applications -> "New Application" ->
   name e.g. "NexLoot" -> "Create". Then "OAuth2" on the left:
   * "Redirects" -> "Add Redirect" -> paste the callback URL from point 2 -> "Save Changes" at the bottom.
   * "Client information": copy the "Client ID". Under "Client Secret" click "Reset Secret" and copy the
     secret (it is shown only once).
   The client secret is like a password. It goes ONLY into Supabase (point 4), never into config.js.
4. Back in Supabase (Discord expanded): turn on "Discord Enabled", paste the Client ID (the long number,
   not the application's name) and the Client Secret -> "Save".
5. In Supabase -> "Authentication" -> "URL Configuration":
   * "Site URL": the address of your website, e.g. https://my-guild-loot.netlify.app -> "Save".
   * "Redirect URLs" -> "Add URL": the same address followed by /**, e.g.
     https://my-guild-loot.netlify.app/** -> "Save URLs". If you also use your own domain, add it too.
6. You: open the website -> "Log in with Discord". The first time, Discord asks whether NexLoot may see
   your name, avatar and email address -> "Authorize". Then pick your character ("That's me") and, via
   your name at the top -> "Unlock as officer …", enter the write password.
   The other officers do the same. Everyone else: log in and pick their character, done.
Without points 2-5 the website shows no login button. Everything else works as before.
Supabase stores name, avatar and email address for every Discord account (Authentication -> Users,
visible only to whoever manages the Supabase project). The website only shows name and avatar.

Assigning Discord accounts (officers, "Admin" tab):
* Players who logged in already are in the list: pick a character on the right -> "assign".
  The × on a character removes the link.
* For players who never logged in, you need their Discord ID: in Discord, Settings -> "Advanced" ->
  turn on "Developer Mode", then right-click the name -> "Copy User ID". Under "Assign a new Discord
  account" enter the ID, a name (optional) and the character -> "assign". When the player logs in
  later, their character is already there.
* A character always belongs to one Discord account only. Anyone picking a character that is taken
  is told to ask an officer.
* "Without Discord" shows who in the guild roster is not assigned to anyone yet.
* Anyone who knows the website's address can log in with Discord and pick a free character. That
  doesn't let them see anything new. If an assignment is wrong, an officer removes it with the ×.

Planning a raid setup (officers, "Raids" tab):
1. "New setup": title (e.g. "Onyxia"), date and time, size 10, 20 or 40 (2, 4 or 8 groups).
2. On the left are the players from the guild roster and everyone with Nex-Coins (search by name or
   class, filter by level). Drag players into a group, onto the "Bench" or to "Not attending". On a
   phone: tap a player, then "here" on the group. At the top the website counts players, tanks,
   healers, damage and classes (roles come from the add-on, see step 7). At most 5 per group.
3. "Save as draft" (officers only) or "Publish" (everyone sees it, and everyone finds their group on
   the start page). "Edit" changes a setup, "Delete" removes it. Choosing a smaller size moves the
   players of the dropped groups to the bench.
4. If two officers edit the same setup at the same time, the second one gets a notice when saving
   ("… changed the setup in the meantime – please reload"). Nobody overwrites the other's changes.
How a published setup gets into the game and to Discord: step 9.

Past raids ("Raids" tab, at the bottom):
* 6 hours after the start, a setup moves from the top to "Past raids". All old setups are there,
  newest first (10 at a time, more with "Load older"). Drafts are not listed.
* Each line shows date, raid, how many from the groups were there (e.g. "18 of 20 there") and where
  your own character was planned and whether it attended. Expanding it shows the whole setup and
  below that the session of that evening (click to open it in the "Sessions" tab), who was missing,
  who jumped in from the bench and who joined without being in the setup (from the session's
  attendance list).
* The website finds the session by itself: the one that started between 3 hours before and 6 hours
  after the raid start. Officers can change that on the expanded raid under "Assign session": another
  session from the 2 days before or after, "no session" or back to "automatic".


9. RAID SETUPS IN THE GAME AND ON DISCORD (add-on 0.30, companion app 1.8.2)
----------------------------------------------------------------------------
* In game: /nex -> "Raid setup" (or /nex setup) shows the published setups from the website: all
  groups with class colors and role, bench, not attending, counts of tanks, healers, damage and
  classes, and your own group at the top ("You: Group 2"). Players who are offline according to the
  guild roster are grayed out. If your group changes, the chat tells you at login.
* Officers and raid leads: "Invite all" invites everyone from the groups who is online (not the
  bench) and turns the group into a raid by itself. "Sort groups" (in a raid, as leader or assistant)
  moves everyone into their group from the setup. Also as commands, e.g. for a macro:
  /nex setup invite and /nex setup sort.
* On Discord (optional): one message per published setup in Raid-Helper style: the raid as the title,
  the date below (everyone sees it in their own time zone), counts of tanks, healers, damage and
  classes, then group by group one player per line with a role icon, finally the bench and "not
  attending". Above the message, everyone in the groups and on the bench is @mentioned, if they are
  linked to Discord on the website (step 8). When the setup changes, the app edits the message (no new
  one). Back to draft or deleted: the message disappears. Even if several officers run the app, only one
  posts. There are no sign-up buttons (a webhook message can't have them) – if you use Raid-Helper,
  better let Raid-Helper post (step 10). The app then posts nothing for setups linked to a Raid-Helper
  event.

How a setup gets into the game:
  "Publish" on the website -> an officer's companion app fetches it (every minute) and writes it into
  WebData.lua -> at that officer's next login or /reload the add-on takes it over and sends it through
  the guild to everyone online. Players who log in later get it from an officer. So: after a change on
  the website, one /reload (as an officer with the app running) and everyone has it.
  /nex setup sync sends the state to the guild again if needed. The add-on only accepts setups from
  officers and raid leads.

Setup:
1. nexloot_konten.sql already ran in step 1.
2. Every officer: companion app 1.8.2 and add-on 0.30.0. All players: add-on 0.30.0. Older versions
   simply ignore the setups.
3. Discord (optional): right-click the N -> "Einstellungen …" (settings):
   * "Raid-Setups posten" (post raid setups) is already ticked. If nothing else is entered, the
     setups go to the same channel as the raid summary (webhook from step 4).
   * A separate channel for the setups: create a webhook there (as in step 4, point 1) and paste it
     into "Webhook Raid-Setups". "Discord testen" sends a test into every channel entered.
   * "Spieler im Setup erwähnen" (mention players in the setup) is ticked too. Without it the message
     has no @mentions. Best set this the same way for all officers with the app.
   Tip: all officers with the app enter the same webhook (or only one of them does). Otherwise a setup
   can end up in another channel when the first one's app is off for a while.
4. Check: right-click the N -> "Status anzeigen" (show status) shows "Raid-Setups fürs Spiel:
   1 veröffentlicht" (raid setups for the game: 1 published) and "Raid-Setups in Discord: an …".
   In game: /reload, then /nex setup.

Class icons like Raid-Helper (optional): a Discord message can only show icons as emojis.
1. On your Discord server: Server Settings -> "Emoji" -> "Upload Emoji", one picture per class. Name
   them after the class: Warrior, Paladin, Hunter, Rogue, Priest, Shaman, Mage, Warlock, Druid
   (German names work too).
2. Get the codes: send this message in a Discord channel (with the \ before each emoji):
       \:Warrior: \:Paladin: \:Hunter: \:Rogue: \:Priest: \:Shaman: \:Mage: \:Warlock: \:Druid:
   Discord then shows the codes instead of the pictures, e.g. <:Warrior:123456789012345678>. Select
   and copy the text of the message (then delete the message).
3. Website -> "Admin" -> "Class icons for Discord": paste the text into the big field -> "Assign".
   The website recognizes the class by the emoji's name and shows the icons to check. Enter anything it
   can't match directly at the class. Then "Save".
4. In the next few minutes the companion app rewrites the messages of the upcoming raids with icons.
Emojis from another server work too (enter the image address or just the number). Then @everyone must
be allowed to "Use External Emojis" in the channel, otherwise it only shows :Name:.


10. CONNECT RAID-HELPER (optional, Raid-Helper Premium recommended)
-------------------------------------------------------------------
* A setup on the website is linked to a Raid-Helper event. You create the event with Raid-Helper in
  Discord as usual, and the players sign up there.
* In the setup editor you pick the Raid-Helper event at the top; title and date are taken over. Every
  player shows how they signed up with Raid-Helper: ✔ signed up, ? tentative or late, B bench,
  ✖ absent. Signed-up players are listed first, "signed up only" hides the others.
* On the setup, a "Raid-Helper" box shows who is placed but absent, tentative or not signed up at all,
  and who signed up but is not placed.
* "Send to Raid-Helper" writes the groups into the event's composition (Raid-Helper's comp tool). The
  first time, Raid-Helper posts it in the event's channel and mentions the players. With Premium the
  post then updates itself, and players can confirm or cancel with buttons. "Send again" sends changes
  (confirmations are kept), "Post again" makes a new post and mentions everyone once more.
* Players who signed up with Raid-Helper go into the composition with their class and spec from there.
  For everyone else the website takes the class from the guild roster and the role from the add-on,
  otherwise the spec with the most talent points, otherwise the usual raid role of the class. Players
  whose class is unknown are left out (the website names them).
* The other way round works too: if you prefer to arrange the groups in Raid-Helper's comp tool,
  "Import from Raid-Helper" in the setup editor puts them into the groups. Slots are matched to
  characters through the Discord link (matching class first, otherwise the favorite character), without
  a link by name. Nothing is stored until "Publish" or "Save as draft" – then the line-up also gets
  into the game.
* The companion app posts no message of its own for these setups. They get into the game as in step 9.

One-time setup (about 10 minutes):
1. In Discord: type /apikey (admins only) and copy the server API key. Also the server ID: Settings ->
   Advanced -> Developer Mode on, then right-click the server icon -> "Copy Server ID".
2. In Supabase -> "Vault" (under Integrations or Database, depending on the version) -> "Add new
   secret":
   * name raidhelper_key, value = the API key
   * name raidhelper_server, value = the server ID
   The key is like a password: don't put it anywhere else. If you create a new one in Discord with
   /apikey, enter the new one here.
3. In Supabase -> "SQL Editor": run "1 Supabase/nexloot_raidhelper.sql". It also turns on the "http"
   extension so that Supabase can ask Raid-Helper.
4. Create the edge function. Raid-Helper does not accept changes (writing groups, announcing) directly
   from the Supabase database. So the database sends them through a small function:
   * In Supabase -> "Edge Functions" -> "Deploy a new function" -> "Via Editor".
   * Replace the example code completely with the contents of "1 Supabase/nexloot-raidhelper.ts".
   * Name it exactly nexloot-raidhelper -> "Deploy function".
   * Then, on the function's "Details", turn off "Verify JWT" (or "Verify JWT with legacy secret") and
     save. The function stores nothing and only forwards to Raid-Helper, with the key the database
     gives it for that one call.
5. Link the players to Discord on the website (step 8). That's the only way the website recognizes
   their sign-ups, and Raid-Helper only mentions linked players.

How to use it:
1. Create the Raid-Helper event in Discord (as usual).
2. Website -> "Raids" -> "New setup" (or "Edit") -> pick the event at the top -> arrange the groups
   (or "Import from Raid-Helper") -> "Publish".
3. On the setup: "Send to Raid-Helper". Raid-Helper posts in the event's channel within seconds.
If Raid-Helper has no composition for an event yet, you get a notice. Open the event's comp tool in
Raid-Helper once, then send again.


HOW THE SYNC WORKS
------------------
* WoW saves the NexLoot data when you log out and on /reload. A few seconds later the companion
  app uploads the new state.
* If the database has newer data (e.g. another officer led a raid while you were offline, or the
  Wednesday decay), the app writes it into the NexLoot folder (file WebData.lua). At your next
  login or /reload the add-on takes it over and shares it with everyone through the guild. Raid
  setups get into the game the same way.
* The add-on never takes over data from the website on top of its own changes that are not
  synced yet. Then the chat says "Webapp-Stand nicht übernommen" (website data not taken over)
  and the app syncs first.
* If the database only has the decay as news and your game has entries of its own, the app
  applies the decay to your game data and uploads both together. Nothing gets lost.
* Conflict: if two officers handed out loot independently (without seeing each other in the game
  or through the app in between), the database state wins for everyone. The app tells you and
  writes a report (click the message). It lists the entries from your game that were not taken
  over, so you can add them with /nex history add or /nex coins.
* If an officer's app has not been running for more than 12 hours, the add-on reminds them at login.
* Supabase also keeps every version (the last 300). To restore one in the SQL Editor:
      select id, rev, created_at, created_by from nexloot_snapshots order by id desc;
      select nexloot_restore('MyGuild', <id>, '<write password>');
* Free Supabase projects are paused after 7 days without use; then the decay does not run either.
  As long as a companion app is running, that doesn't happen. A missed decay is made up as soon as
  the project runs again. Emergency in game: /nex decay now (only takes coins off if a week is
  really missing).


SECURITY
--------
* The website and the public key can only read coins, loot and history. Writing needs the write
  password. The app stores it with Windows encryption, readable only by your Windows user. The same
  goes for the Discord webhooks and the email app password.
* Discord login (step 8): logged-in players can only link their own characters. Only officers can plan
  setups and assign accounts, and you only become an officer with the write password. Who someone is
  comes straight from Discord and can't be faked. The Discord client secret is only in Supabase.
* The add-on only accepts raid setups (step 9) from officers and raid leads.
* Raid-Helper (step 10): the API key is only in the Supabase Vault. The website, the add-on and the
  companion app never see it; only officers can ask Raid-Helper and send from the website. The edge
  function only gets the key from the database for a single call and doesn't store it.
* The secret Supabase key (secret / service_role) is not needed anywhere.
* Send the connection code to officers privately only; it contains the write password.


TROUBLESHOOTING
---------------
* The N is red: right-click -> "Status anzeigen" (show status) or "Protokoll öffnen" (open log).
* Windows says "Windows protected your PC" or a virus scanner complains: the app is a PowerShell
  script that runs hidden in the background. Unblock the ZIP before unzipping (step 3.1). You can
  read the source code in the .ps1 files with any text editor.
* A black terminal window in the taskbar (Windows 11): Windows Settings -> System -> For developers
  -> Terminal -> "Windows Console Host". Don't close that window, or the app quits too.
* Email backup: "Anmeldung beim Mailserver abgelehnt" (mail server login refused): create a new app
  password and enter it (the normal Gmail password doesn't work). After an error the app tries
  again 30 minutes later.
* Discord: "Webhook gibt es nicht mehr" (webhook no longer exists): it was deleted in Discord.
  Create a new one and enter it in the settings. "zu viele Nachrichten" (too many messages):
  Discord slows down for a moment; the app retries by itself.
* "falsches Schreib-Passwort" (wrong write password): enter the right password in the settings.
  The guild ID must also be spelled exactly as in nexloot.sql.
* "Gildenübersicht: In Supabase fehlt noch nexloot_gilde.sql" (nexloot_gilde.sql is missing in
  Supabase): step 1, point 4. An empty guild tab ("No guild roster yet"): an officer with add-on 0.29
  and app 1.7.0 or newer has to log out or /reload once. In game, /nex guild shows whether the add-on
  has the roster.
* "Log in with Discord" is missing at the top right: Discord is not enabled in Supabase yet (step 8,
  point 4). Then reload the website.
* Discord says the client_id "is not snowflake" when logging in: Supabase has something other than the
  number as "Client ID", e.g. the application's name (step 8, point 4).
* "Unable to exchange external code": the client secret in Supabase is wrong. "Reset Secret" in Discord
  and enter the new secret in Supabase (step 8, points 3 and 4).
* After logging in with Discord you end up on "localhost" or an error page: in Supabase under "URL
  Configuration", set the Site URL to the website's address (step 8, point 5). If Discord says
  "Invalid OAuth2 redirect_uri": the Discord application's OAuth2 -> Redirects must contain exactly the
  callback URL from Supabase (step 8, point 3).
* "Raid setups are not set up yet" or "… the new nexloot_konten.sql is missing": run nexloot_konten.sql
  in the SQL Editor (step 1, point 4). Then reload the website.
* The raid setup is missing in game ("No raid setup yet"): an officer with add-on 0.30 and companion
  app 1.8.x has to /reload once after publishing (step 9). The app's status must say
  "Raid-Setups fürs Spiel: … veröffentlicht".
* "Invite all" reports "Not found (check the name)": check the name in the setup – it must be spelled
  exactly as in the game.
* Discord shows :Name: instead of a class icon: the emoji doesn't exist (any more), or it comes from
  another server and @everyone may not use external emojis in the channel.
* A player isn't mentioned on Discord: their character isn't assigned to a Discord account on the
  website yet ("Admin" tab). Players who are neither in a group nor on the bench are never mentioned.
* "… is already linked to another Discord account": someone else picked that character. An officer can
  assign it correctly in the admin tab.
* A past raid shows the wrong session or "no session": expand the raid and pick the right one under
  "Assign session" (officers only).
* The setup editor has no "Raid-Helper event" field: nexloot_raidhelper.sql is missing (step 10,
  point 3). If it says "Raid-Helper: not set up yet": the names in the Vault must be exactly
  raidhelper_key and raidhelper_server (step 10, point 2).
* "Raid-Helper rejects the API key": check the server key with /apikey in Discord (not the personal
  one from /usersettings) and enter it in the Vault again.
* "In Supabase fehlt noch die Edge Function nexloot-raidhelper" (the edge function is missing in
  Supabase): step 10, point 4 (exactly that name). "Die Edge Function nexloot-raidhelper lässt den
  Aufruf nicht zu" (the edge function does not allow the call): turn off "Verify JWT" on the function's
  "Details".
* "Raid-Helper has no composition for this event yet": open the event's comp tool in Raid-Helper once,
  then send again.
* "The Raid-Helper event belongs to a different Discord server": check the server ID in the Vault.
* "Raid-Helper cannot be reached right now (…)": the brackets say at which step the connection broke
  off (GET = reading, PATCH = changing the composition, POST = announcing). Wait a few minutes and send
  again. If it stays like that, run this in the SQL Editor (with your project address):
      select * from nexloot_rh_check(null, 'https://abcdefgh.supabase.co');
  It plays the sending of the most recently changed setup step by step (without posting on Discord)
  and shows what Raid-Helper answers at each step.
* A player has no ✔ in the editor although they signed up with Raid-Helper: their character isn't
  linked to their Discord on the website ("Admin" tab).
* No connection to the database (error under "Status anzeigen"): check your internet. If the
  Supabase project is paused, open it in Supabase and click "Resume project".
* The app can't write WebData.lua: your Windows user needs write access to the WoW folder (normally
  the case, otherwise add-ons wouldn't work either).

Uninstall: right-click -> turn off "Mit Windows starten" -> "Beenden" (quit). Then delete the app
folder, the folder %APPDATA%\NexLootCompanion and the file WebData.lua in the NexLoot add-on folder.
